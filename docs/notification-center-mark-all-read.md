# Notification Center: mark all read (#60)

The existing center offers “Tümünü okundu işaretle” above its list while unread records exist. It disables repeat submission, refreshes the canonical count and rows after acknowledgement, and retains an error message on any failed/uncertain result. Empty/read inboxes have no bulk action.

`GET /api/notifications/` now adds `readBefore` (server clock). `PATCH /api/notifications/read-all` accepts only `{before: <ISO timestamp>}` and uses the authenticated principal. A single idempotent update covers all unread rows, beyond the list's 100-row window, whose scheduled and delivered timestamps are strictly before the observed boundary. It changes only `readAt`. Future boundaries, unexpected body fields and invalid input are rejected. New deliveries, pending schedules, other users and previously read timestamps are untouched.

Android uses the existing `notificationInboxJson` / `markNotificationRead` bridge; no new native method or APK is needed. The client captures existing local IDs and timestamps, waits for server success, marks matching local-only rows, and mirrors acknowledged server read state into local push matches. It verifies native persistence by reading back. New arrivals/replaced IDs are excluded. Optional validated `nativeServerIds` on the existing inbox GET includes the current user's matching delivered rows outside the newest 100, avoiding duplicate badge counts and allowing cross-device read reconciliation. OS-tap reads still upload through the existing individual endpoint. Account changes invalidate pending client results and native writes.

Partial failures are recoverable: no record is removed, a later inbox refresh reconciles server-backed read state, and a retry safely finishes remaining local rows. A failed server request never starts local-only bulk writes. No unverified success toast is emitted. A lost response followed by an acknowledged server write is shown with the error and refreshed actual rows.

Integration: backend endpoint/response must be available before enabling the refreshed frontend. The old backend cannot supply a boundary, so the bulk button stays disabled. No migration, preference, delivery schedule, category, payment, health-access or Coach sync change. Existing individual navigation remains available.

Targeted validation lives in `notification-center-mark-all-read.yml`: PostgreSQL-backed authenticated HTTP/service checks, six adapter cases (130 rows, mixed/native, single flight, failure/retry, account switch, restart/readback), and eight browser cases including 390/412/430/1440 px, empty state, logout/login, uncertain response and the existing Android bridge contract. Android bridge tests are a browser simulation; no physical device result is claimed. No broad legacy suite, deploy or APK job is run.
